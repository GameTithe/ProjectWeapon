# KAN-80 슬롯 한도와 초과 획득

`InventorySlotCapacity`는 장착과 운반 슬롯 수를 각각 받는다. 기본 설정은 장착 2칸, 운반 3칸 가안이다. 구성 시 다른 0 이상의 값을 넘길 수 있다. 슬롯 번호는 각 범주의 0부터 시작한다. 초기 실물 목록에 구성 범위를 벗어난 장착·운반 위치가 있으면 구성 오류로 보고하며, 기존 데이터에 더 많은 슬롯이 필요하면 저장 데이터에 맞는 한도를 명시한다. [KAN-80](https://gametithe.atlassian.net/browse/KAN-80) · [KAN-20 설정 틀](KAN-20-balance-settings.md)

## 획득과 교체

- 줍기 쪽에서 아직 이 인벤토리에 없는 획득 대상 실물 레코드를 `TryPickup(loot)`에 넘긴다. 빈 운반 슬롯이 있으면 가장 낮은 번호에 해당 실물을 배치하고 `PickedUp`을 반환한다. 기존 실물 ID, 무기 원형과 출처를 유지한다.
- 빈 운반 슬롯이 없으면 `ChoiceRequired`와 당시 운반 물품의 읽기 전용 목록을 반환한다. 선택을 표시하는 동안 기존 인벤토리와 획득 대상은 그 위치에 남는다. 운반 용량이 0이면 `NoCarryCapacity`다.
- 선택을 취소할 때는 `ResolvePickup(choice, null)`을 호출한다. 선택은 종료되며 기존 실물과 슬롯은 그대로다. 선택된 실물 ID를 전달하면 그 실물의 슬롯에 새 무기를 넣고, 기존 물품은 `Displaced`로 반환한다. `Displaced`의 위치는 직전 슬롯을 기록하며 이 인벤토리에서 여전히 소유한다는 뜻은 아니다. 호출자는 새 무기가 수락된 경우에만 월드 객체를 반영하고, 반환된 실물의 배치나 처리 정책을 결정한다.
- 다른 인벤토리가 만든 선택과 무효인 레코드는 거절한다. 이미 가진 실물 ID를 다시 받지 않는다. 운반 슬롯이 바뀌었거나 완료·취소한 선택은 오래된 요청으로 거절한다. 장착이나 창고의 ID를 운반 교체 대상으로 지정할 수 없다.
- 이동, 즉시 획득, 교체와 조회는 같은 잠금 안에서 처리된다. 획득은 운반 공간만 사용한다. 출격 반입·대여 배치·폐기·소유권 정산과 월드 트리거 중복 차단은 후속 작업에서 연결한다. [KAN-45](https://gametithe.atlassian.net/browse/KAN-45) · [KAN-66](https://gametithe.atlassian.net/browse/KAN-66) · [KAN-71 이동 계약](KAN-71-inventory-move.md)

## 재현 절차

Unity 프로젝트 루트에서 실행한다.

```powershell
unity test . --mode EditMode --filter ProjectWeapon.Inventory.Tests --output "$env:TEMP/KAN-80-editmode.xml" --timeout 900
```

| 입력 | 기대 결과 |
| --- | --- |
| 기본 2/3에서 3번째 장착 또는 4번째 운반 위치 이동 | 구성 범위 밖 이동 거절 |
| 1칸 운반 가방이 찬 상태에서 줍기 후 취소 | 기존 물품과 획득 대상의 위치 유지 |
| 2칸 운반 가방에서 기존 실물 ID 하나를 교체로 선택 | 지정한 실물만 반환되고 새 무기가 해당 슬롯을 사용 |
| 운반 물품이 선택 후 이동했다가 돌아옴 | 앞선 선택이 무효화되고 새 선택은 생성 가능 |
| 같은 획득의 동시 재시도 또는 같은 물품을 대상으로 교체 동시 확정 | 한 번만 획득되고 이전 물품이 중복 제거되지 않음 |
