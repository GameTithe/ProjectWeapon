# KAN-70 플레이어 체력·피해·사망

`PlayerHealth`는 한 번의 출격에서 사용할 체력을 보관한다. 호출자가 양의 정수로 최대 체력을 제공하며, 초기 체력은 최대치다. 피해량은 양의 정수이며, 적용 피해는 요청 피해와 현재 체력 중 작은 값이다. 체력이 0이면 이후 피해를 거절한다. 음수 시각과 양수가 아닌 피해도 거절한다. [KAN-70](https://gametithe.atlassian.net/browse/KAN-70)

- 수락된 타격마다 `DamageApplied`를 한 번 발행한다. 이벤트에는 이전 체력, 현재 체력, 실제 감소량과 탐험 시계의 유효 시각을 담는다.
- 체력이 양수에서 0으로 떨어지면 같은 피해의 `Died`를 한 번 더 발행한다. 이벤트를 받는 시점에는 새 체력이 반영돼 있다.
- 체력과 피해에 사용할 기본값, 피격 무효 조건, 회피, 이동에 따른 취소는 각 전투 계약에 따른다. 장차 소수 피해를 쓰면 적용할 정수 단위는 승인된 변환 규칙을 전달받아 정한다. [KAN-190](https://gametithe.atlassian.net/browse/KAN-190)

## 탐험 중 타격 연결

탐험의 타격 수신 계층은 `PlayerRunDamage.ApplyHit`에 현재 `RunId`, 판정 시각, 수락 가능한 피해량과 그 프레임의 신호 목록을 전달한다. 프레임 조정 계층은 관측을 마친 현재 프레임의 유효 타격만 유효 시각 순서로 넘긴다. 같은 프레임에서 앞선 유효 시각에 이미 귀환 성공이 성립한 경우, 그 뒤의 타격은 호출자가 제외한다. 다른 런, 종료된 런, 제한 만료 시각과 그 이후의 타격은 체력에 반영되지 않는다.

수락된 피해가 활성 채널링 시도 중 발생했다면 그 시도 ID로 `RunSignal.CancelExtraction`을 추가한다. 0에 도달하면 `RunSignal.PlayerDied`도 추가한다. 신호 목록에 추가한 뒤 체력 이벤트를 발행한다. 프레임 조정 계층은 귀환 완료와 시간초과 입력도 같은 목록에 모으고, 한 번만 `RunState.ProcessSignals`를 호출한다. 동시 신호의 우선순위와 정산 요청은 기존 `RunResultFinalized` 계약을 따른다. ## 검증 절차

PowerShell에서 Unity 프로젝트 루트를 열고 실행한다.

```powershell
unity test . --mode EditMode --filter ProjectWeapon.Player.Tests --output "$env:TEMP/KAN-70-editmode.xml" --timeout 900
```

| 상황 | 확인 항목 |
| --- | --- |
| 일반 피해와 잘못된 입력 | 체력·피해 이벤트의 실제 감소량과 유효 시각, 양수가 아닌 최대 체력·피해·음수 시각 거절 |
| 정확히 0이 되는 피해와 초과 피해 | 체력 0 고정, 적용 피해는 남은 체력만큼, 추가 타격에도 사망 이벤트 1회 |
| 제한 만료 시각과 그 이후의 피해 | 체력·이벤트·신호가 유지되고 RunState가 시간초과 확정 |
| 귀환 완료와 같은 시각의 비치명 피해 | 입력 순서를 바꿔도 진행 중인 시도만 취소되고 탐험으로 복귀 |
| 귀환 완료와 같은 시각의 치명 피해 | 입력 순서를 바꿔도 사망 결과 한 번 확정, 재처리해도 결과 이벤트 추가 없음 |
| 앞선 시도의 취소가 늦게 전달됨 | 다음 시도 유지 |
