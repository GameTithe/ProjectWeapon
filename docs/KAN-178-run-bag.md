# KAN-178 탐험 가방

[Jira KAN-178](https://gametithe.atlassian.net/browse/KAN-178) · [KAN-190 전투와 귀환 조작](https://gametithe.atlassian.net/browse/KAN-190)

## 연결

1. 탐험 Canvas와 EventSystem에서 화면을 채우는 RectTransform에 `RunBagPanel`을 붙인다. `Initialize(actions, catalog, font)`에 탐험의 무기 카탈로그와 한글 TMP 폰트를 연결한다. 프로젝트에 TMP Essential Resources를 설치한다.
2. `RunBagActions`에 현재 `RunState`와 런 ID, 동일한 탐험 인벤토리와 `LootPickupCoordinator`, 장착 슬롯 변경 가능 조건, 전리품 배치 함수를 연결한다. 장착 가능 조건은 현행 공격·스킬 상태를 반영하는 조회 함수다.
3. 가방 버튼에서 `Open()`을 호출하고 탐험의 인벤토리나 상태가 바뀌면 `Refresh()`를 호출한다. 화면을 닫을 때 `Close()`를 호출한다.
4. 열린 동안과 닫은 프레임에는 `OwnsGameplayInput`이 참이다. 호스트가 이를 보고 이동·회피·스킬 입력을 막고, 이미 잡힌 조이스틱 입력을 해제한다. 가방 조작으로 시작된 포인터가 해제되기 전에는 호스트가 해당 입력을 게임에 재전달하지 않는다. 시계, 적 행동, 피격과 이전에 시작한 행동은 계속 진행한다.

전리품 배치 함수는 센서 반경 밖의 유효한 위치에 **새 비활성 `WorldLoot`**와 필요한 콜라이더를 준비해 반환한다. 배치할 수 없으면 null을 반환하고 임시 객체를 정리한다. 획득 처리도 같은 코디네이터를 사용한다. 버리기가 수락되면 서비스가 소지품을 제거하고 코디네이터가 획득 기록을 갱신한 뒤 객체를 활성화한다. 실물 ID와 대여 여부는 유지된다.

## 재현

- 기본 용량 설정의 장착 두 칸과 운반 세 칸을 확인한다. 무기를 선택한 뒤 다른 슬롯을 누르면 빈 칸으로 이동하거나 점유 중인 무기와 교체된다. 중간에 대상 슬롯이 바뀌면 다시 선택하도록 표시한다.
- 무기 선택 후 버리기를 누른다. 유효한 위치이면 소지품이 빠지고 같은 실물이 바닥에 나타난다. 그 위치로 이동하면 다시 주울 수 있다. 배치가 거절되면 소지품은 유지된다.
- 공격·스킬로 장착 변경이 잠기면 장착 칸을 거치는 요청만 거절된다. 귀환 중 가방은 읽기 전용이고, 귀환 신호를 보내지 않는다. 사망이나 시간 초과로 탐험을 끝내면 창이 닫히며 이전 요청도 무효다.
- 가방을 열고 놔두면 시간이 계속 흐른다. 가방 조작 터치로 이동·회피·스킬이 발동하지 않는지 호스트 입력과 함께 확인한다.

Unity Test Runner의 EditMode에서 `ProjectWeapon.RunBagUI.Tests`를 실행한다. 실제 인벤토리·전리품 코디네이터·런 상태를 사용한다. 가방 UI에는 창고 이동이나 정산 기능이 없다.
