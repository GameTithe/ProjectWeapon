# KAN-50 합성 QA 로그 재집계

[Jira KAN-50](https://gametithe.atlassian.net/browse/KAN-50) · [KAN-48 지표 이벤트 계약](https://gametithe.atlassian.net/browse/KAN-48)

## 로컬 재현

Unity 6000.6.9f1에서 EditMode `QaReplayTests`를 실행한다. `ActualFileReloadReproducesAllSevenMetrics`는 전용 임시 디렉터리에 실제 UTF-8 NDJSON을 쓰고 파일을 다시 읽는다. 테스트 종료 후 디렉터리를 정리한다. 이미 열린 Editor에서는 아래 명령으로 같은 픽스처를 실행한다.

```powershell
unity command test run --project-path . -- --mode editor --filter QaReplayTests
```

자체 QA 실행기는 합성 식별자를 생성하고 `QaEventLog.Append(path, events)`로 로컬 파일에 이벤트를 쓴다. 읽기가 끝난 뒤에는 해당 실행의 전용 파일을 정리하고, 합성 원천은 최대 7일간 보관한다. `QaEventLog.Replay(path, window)`는 기입한 계약 버전, 합성 범위 ID, 집계 시작·끝, 관측 끝을 사용한다. 원천 파일이 없으면 보고서를 반환하지 않는다. 기존의 빈 파일은 코인 합계 0과 분모가 없는 비율을 반환한다. 읽을 수 없는 행은 원문 대신 행 번호를 보고한다.

`QaRunCapture`는 합성 탐험의 수락된 출격, 신규 비대여 실물 획득, 실제 귀환 시작·취소, 확정 종료, 저장된 영수증을 연결한다. 영수증을 다시 기록할 때는 처음 저장을 관측한 합성 시점을 그대로 사용한다. 코인과 도감은 저장 성공이 확인된 결과에서만 발행한다. 구형 영수증에 없는 도감 델타는 만들지 않는다. 광고는 표시·검증·저장·실패를 합성 이벤트로 제공한다. 개발용 파일에는 개인정보나 광고 원본 토큰 필드가 없다.

## 계산 경계

- 집계 기간은 시작을 포함하고 끝을 제외한다. 관측 끝도 제외하며, 기간 밖 이벤트도 관측 끝 이전이면 기간 내 사건의 후속 상태를 확인할 수 있다. 뒤늦게 추가된 이벤트는 기록된 합성 시점으로 재집계한다.
- 출격, 정산, 코인, 도감처럼 다른 종류는 같은 키를 사용할 수 있다. 동일 종류·키·내용은 한 번만 남기고, 같은 종류·키에 내용이 여러 개면 해당 키를 제외한다.
- `T`, `H`, `W`는 실행기의 명시적 실험 값이다. 생략하면 해당 지표를 표시하지 않는다. 관측 경계에 있는 `T`와 `W`의 마지막 시점도 후속 사건의 유효 범위에 포함되므로, 관측 끝이 그 시점을 넘어야 아직 후속 증거가 없는 항목을 확정한다. 선택 뒤 취소는 해당 탐험에서 처음 집계한 귀환 시도와 관측 끝 이전에 수락된 취소를 연결한다.
- 표시된 광고는 검증과 저장 확정이 모두 있거나 관측된 표시 후 실패가 있을 때 완료율 분모에 들어간다. 결과 대기는 별도 수치이며 광고를 보기 전의 취소와 채우기 실패도 별도 집계다. 양립할 수 없는 성공·실패 기록은 모순 수치에 남긴다.
- 도감 속도는 같은 시작 상태를 가진 합성 범위의 신규 회수 원형과, 기간 내 확정 종료한 탐험의 시작·종료 차이를 사용한다. 미리 등록된 원형은 중복으로 세지 않는다.

## 합성 픽스처 기대값

| 지표 | 기대값 |
| --- | --- |
| 귀환 성공률 | 2/4, 정산 대기 1 |
| 신규 획득 직후 귀환 선택률 | 2/4, 선택 뒤 취소 1/2 |
| 상위 등급 출격 사용률 | 2/6 |
| 무기 상실 후 재출격률 | 1/2 |
| 확정 코인 획득·소비 | +20, 소비 12, 순증 8 |
| 광고 보상 완료율 | 3/4, 결과 대기 1, 표시 전 취소 1, 채우기 실패 1 |
| 도감 등록 속도 | 완료한 탐험 60초 동안 2종, 시간당 120종 |

표의 시간·등급은 유한한 테스트 값이다. 제품 집계 기준은 승인된 버전과 별도 설정이 필요하다.
