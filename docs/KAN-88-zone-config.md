# 5구역 설정과 검증

[도메인 계약](KAN-19-domain-contracts.md)의 `ZoneDefinition`을 실제 Unity 데이터로 저장한다. [KAN-88](https://gametithe.atlassian.net/browse/KAN-88)

## 데이터 수정

Unity Project 창에서 `Assets/ProjectWeapon/Dungeon/PrototypeZoneCatalog.asset`을 선택해 구역 데이터를 수정한다. 시간 단위는 초다. 보상 확률 배열은 1등급부터 5등급까지 순서대로 입력하며, 단위는 basis points(bp)다. 100bp가 1%이고 한 구역의 합계는 10,000bp다. 두 범위 끝값은 포함하며 범위 바깥 확률은 0이어야 한다.

| ID | 테마 | 권장 등급 | 보상 범위 | 제한시간 (초) | 상자 확률 (1~5등급, bp) |
| --- | --- | --- | --- | --- | --- |
| 1 | 버려진 폐성 | 1 | 1–2 | 480 | 8,500 / 1,500 / 0 / 0 / 0 |
| 2 | 지하 감옥 | 2 | 1–3 | 600 | 4,500 / 4,500 / 1,000 / 0 / 0 |
| 3 | 저주받은 숲 | 3 | 2–4 | 720 | 0 / 4,500 / 4,500 / 1,000 / 0 |
| 4 | 마왕의 요새 | 4 | 3–5 | 720 | 0 / 0 / 6,000 / 3,500 / 500 |
| 5 | 심연의 성역 | 5 | 4–5 | 900 | 0 / 0 / 0 / 8,500 / 1,500 |

## 런타임에서 읽기

런타임 컴포넌트가 카탈로그 에셋을 참조하고 구역 목록을 열거나 출격할 때 `GetZones()` 또는 `GetZone(zoneId)`를 호출한다. 두 API가 전체 카탈로그의 유효성을 확인한 뒤 읽기 전용 데이터를 반환한다. 잘못된 데이터 또는 미등록 ID는 예외를 일으킨다. 권장 등급은 UI 안내용 값이다. 입장과 구역 해금은 별도 기능에서 판단한다.

## 테스트 재현

저장소 루트에서 Unity 6000.6.9f1 EditMode 테스트를 실행한다.

```powershell
unity test . --mode EditMode --filter ProjectWeapon.Dungeon.Tests.ZoneCatalogTests --output "$env:TEMP/KAN-88-results.xml"
```

테스트는 실제 카탈로그 에셋에서 각 구역의 가안을 읽고, 메모리에 복제한 카탈로그에 잘못된 입력을 만든다. 권장 등급과 보상 범위 경계, 시간 0과 음수, 구역 ID 중복·미등록, 확률 개수와 개별 범위, 합계 9,999와 10,001bp, 보상 범위 밖 확률을 검증한다. 단일 보상 등급의 10,000bp와 양수 시간의 하한도 확인한다.
